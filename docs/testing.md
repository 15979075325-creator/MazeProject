# MazeProject 测试说明

## 一、自动测试

GitHub 上的 `.github/workflows/tests.yml` 会在以下情况自动运行：

- 向 `main`、`feature/member-a` 或 `feature/member-b` 推送代码。
- 创建或更新目标为 `main` 的 Pull Request。

工作流会在 Linux 环境编译主程序，并运行求解器测试和项目测试。仓库首页徽章显示当前测试状态。

Windows 双击项目根目录的 `test.bat`。成功时应依次看到：

```text
ALL TESTS PASSED
ALL PROJECT TESTS PASSED
All tests succeeded
```

自动测试覆盖：

- BFS、Dijkstra、A* 的直线、转弯、无解、起终点相同和非法输入。
- 三种算法在无权迷宫中的最短路径长度一致。
- DFS 生成结果连通、边界为墙并满足树结构。
- 重复生成会重置迷宫；固定种子可复现。
- Maze 尺寸、导入网格、越界访问和修改。
- 文件读写、空格、CRLF、错误尺寸、非法字符和截断文件。

## 二、主程序功能测试

双击 `build.bat`，按下列顺序检查。

### 1. 固定种子

两次选择 `1`，都输入：

```text
15 21 12345
```

两次迷宫应完全相同。换成种子 `54321` 后，迷宫应不同。种子输入 `0` 时，应显示本次实际种子。

### 2. 三种算法

分别选择 `4`、`5`、`6`。BFS、Dijkstra 和 A* 的路径长度应相同。选择 `7` 后，应显示三种算法的长度和耗时，并提示长度一致。

### 3. 坐标与键盘编辑

- 选择 `2`，把普通格子在墙和通路之间切换；旧路径应清除。
- 尝试修改 `S` 或 `E`，操作应被拒绝。
- 选择 `10`，使用 `W/A/S/D`、方向键和空格编辑；`Q` 应返回菜单。
- 光标不得移出迷宫边界。

### 4. 起点和终点

选择 `3`，把起点和终点设到两个不同的通路格。越界、墙格或相同坐标应被拒绝。修改成功后重新寻路应从新的 `S` 到新的 `E`。

### 5. 保存与读取

选择 `8` 保存为 `maze_test.txt`，编辑迷宫后选择 `9` 重新读取。迷宫、`S` 和 `E` 应恢复，旧路径应清除。读取不存在或格式错误的文件时，当前迷宫应保持不变。

### 6. 无解

使用选项 `2` 或 `10` 封住起点的所有出口，再运行 `4`、`5`、`6` 或 `7`。所有算法都应报告无解。

### 7. 路径动画

先运行任意一种寻路算法，再选择 `11`。路径应从 `S` 到 `E` 逐格出现。重新生成或编辑导致路径清除后，直接选择 `11` 应提示先寻路。

## 三、提交前检查

提交 GitHub 前确认：

- `test.bat` 全部通过。
- `build.bat` 编译并运行成功。
- 不提交 `.exe`、临时迷宫文件或编辑器缓存。
- `main`、`feature/member-a`、`feature/member-b` 合并后指向同一已验证提交。
