# 迷宫生成算法详解 —— DFS 递归回溯

> 对应代码：`include/generator/DfsGenerator.h`、`src/generator/DfsGenerator.cpp`
> 阅读前提：了解二维 vector、递归、`std::shuffle`

---

## 1. 我们要生成什么样的迷宫

### 1.1 字符约定（全项目统一，见 docs/interface.md）

| 字符 | 含义 |
|:---:|------|
| `#` | 墙（不可通行） |
| `' '`（空格） | 通路 |
| `S` / `E` | 起点 / 终点（生成阶段不含，由主流程标记） |

### 1.2 目标产物：完美迷宫（Perfect Maze）

满足两条性质的迷宫：

1. **全连通**：任意两个通路格之间都能走过去（不存在孤岛）
2. **无环**：任意两点之间**有且只有一条**路径

> 性质 2 正是本项目要求 BFS / Dijkstra / A* 三种算法算出的路径长度必然一致的根源——最短路径就是唯一路径。

### 1.3 实际效果（21×21）

```
#####################
#S#    .....#.....# #
#.#####.###.#.###.# #
#.......#...#.#...# #
#########.###.#.### #
#       #.....#...# #
# ##### #########.# #
#   # #   #.....#.# #
#####################
```

## 2. 算法总览

**名称**：递归回溯（Recursive Backtracker），深度优先搜索（DFS）家族的经典迷宫生成算法。

**一句话概括**：从一块"实心石头"（全 `#`）里，让一把随机方向的铲子从起点开始挖，挖到没路可挖就回退到上一个岔路口，直到所有房间都被挖通。

```
全墙初始化          随机挖路（递归）           回退收尾
#########        #########              #########
#########   →    #.###.###      →       #   #   #
#########        #.#...###              # ###   #
#########        #.###.###              #     # #
#########        #########              #########
```

---

## 3. 前置约定：为什么宽高必须是奇数

迷宫采用**房间-墙交替**的结构：

- **房间**（会被挖成路的格子）位于**奇数坐标**：(1,1)、(1,3)、(3,1)…
- **墙**位于偶数坐标或边界上：房间与房间之间永远隔着一堵墙

以 5×5 为例（`·` 表示房间位置）：

```
    c=0  c=1  c=2  c=3  c=4
r=0  #    #    #    #    #      ← 边界墙
r=1  #    ·    #    ·    #      ← (1,1)、(1,3) 是房间
r=2  #    #    #    #    #      ← 房间隔墙
r=3  #    ·    #    ·    #      ← (3,1)、(3,3) 是房间
r=4  #    #    #    #    #      ← 边界墙
```

- 尺寸为奇数 → 最外圈恰好全是墙，房间恰好铺满内部
- 若是偶数，最后一行/列的结构会破坏（多出一列无法配对的墙），所以构造函数强制校验：

```cpp
if (w < 3 || h < 3 || w % 2 == 0 || h % 2 == 0 || ...) {
    throw std::invalid_argument("DfsGenerator: w/h 必须是不小于 3 的奇数");
}
```

## 4. 代码逐段走读

### 4.1 构造函数：校验 + 全墙初始化

```cpp
DfsGenerator::DfsGenerator(unsigned w, unsigned h)
    : _grid(), _w(w), _h(h) {
    // 参数校验（≥3 的奇数，且不超出 int 范围）
    ...
    // 初始化为 h 行 w 列、全部填 '#'
    _grid.assign(h, std::vector<char>(w, '#'));
}
```

`assign(h, std::vector<char>(w, '#'))`：造 h 个"长度为 w、全是 `'#'` 的一维数组"，组成二维网格。此刻它是一块实心石头。

### 4.2 generate()：入口

```cpp
void DfsGenerator::generate() {
    _grid.assign(_h, std::vector<char>(_w, '#'));   // 重新填满，支持重复生成
    carve(1, 1);                                    // 从左上角第一个房间开始挖
}
```

起点固定 `(1,1)`；终点由 `goal()` 返回 `(h-2, w-2)`——两个方向数过来的第一个奇数房间，即右下角。

### 4.3 carve(r, c)：递归核心（三步）

```cpp
void DfsGenerator::carve(int r, int c) {
    // 步骤①：当前格挖成通路（标记"已访问"）
    _grid[r][c] = ' ';

    // 步骤②：四个"隔一跳"的方向，随机打乱 —— 随机性的唯一来源
    std::vector<std::pair<int, int>> dirs = {{-2, 0}, {2, 0}, {0, -2}, {0, 2}};
    std::shuffle(dirs.begin(), dirs.end(), rng());

    // 步骤③：依次尝试每个方向
    int rows = static_cast<int>(_grid.size());
    int cols = static_cast<int>(_grid[0].size());
    for (const auto& d : dirs) {
        int dr = d.first, dc = d.second;
        int nr = r + dr, nc = c + dc;
        if (nr >= 0 && nr < rows && nc >= 0 && nc < cols   // 目标在界内
            && _grid[nr][nc] == '#') {                     // 且"仍是墙"（没访问过）
            _grid[nr][nc] = ' ';                    // 挖目标房间
            _grid[r + dr / 2][c + dc / 2] = ' ';    // 打通中间那堵墙
            carve(nr, nc);                          // 递归：从新房间继续挖
        }
    }
    // 四个方向都试完 → 函数返回 = "回溯"到上一个岔路口
}
```

**三个关键点：**

**（a）步长为什么是 2？**
`{-2,0}` 等偏移表示"跨过一堵墙、跳到隔壁房间"。`dr/2, dc/2` 恰好是中间墙的坐标——例如从 (1,1) 向右 `(0,+2)`：目标房间 (1,3)，中间墙 (1,2)。

**（b）随机性从哪来？**
只有第②步的 `std::shuffle`。它随机排列四个方向的**尝试顺序**；顺序不同 → 挖路的先后不同 → 最终迷宫形态不同。挖路规则本身是确定的，**随机 = 打乱选择顺序**。

**（c）`== '#'` 检查的双重含义**
一个格子还是 `'#'`，意味着它从未被挖过 = 未访问。已挖成 `' '` 的房间直接跳过：
- 不会把两个已连通的区域再打通 → **无环**的保证
- 不会挖到界外（配合界内检查）→ 边界完好

## 5. 完整示例：5×5 迷宫的生成全过程

假设两次 shuffle 的结果分别为 `下→右→上→左` 和 `右→上→下→左`。

**Step 0：初始化（全墙）**

```
#####
#####
#####
#####
#####
```

**Step 1：`carve(1,1)`** —— 挖开 (1,1)，shuffle 后先试"下"

```
#####
# ###     (1,1) → ' '
#####
#####
#####
```

**Step 2：向下** —— 目标 (3,1) 是墙 → 挖 (3,1) 和中间墙 (2,1)，递归 `carve(3,1)`

```
#####
# ###
# ###     (2,1) → ' '
# ###     (3,1) → ' '
#####
```

**Step 3：在 `carve(3,1)` 中向右** —— 挖 (3,3) 和中间墙 (3,2)，递归 `carve(3,3)`

```
#####
# ###
# ###
#   #     (3,2)、(3,3) → ' '
#####
```

**Step 4：在 `carve(3,3)` 中向上** —— 挖 (1,3) 和中间墙 (2,3)，递归 `carve(1,3)`

```
#####
# # #     (1,3) → ' '
# # #     (2,3) → ' '
#   #
#####
```

**Step 5：四处碰壁，逐层回退**
- `carve(1,3)`：上出界、右出界、下(3,3)已访问、左(1,1)已访问 → 返回
- `carve(3,3)`：其余方向出界或已访问 → 返回
- `carve(3,1)`：上(1,1)已访问、其余出界 → 返回
- `carve(1,1)`：右(1,3)已访问、上/左出界 → 返回

**最终迷宫：**

```
#####
# # #
# # #
#   #
#####
```

验证：4 个房间、3 条通道，恰好是一棵树——完美迷宫。
从 start (1,1) 到 goal (3,3) 的唯一路径：`(1,1)→(2,1)→(3,1)→(3,2)→(3,3)`。

## 6. 随机性原理与可复现

### 6.1 随机引擎

`rng()` 来自 `src/core/Utils.cpp`（成员A维护），全项目共享一个引擎：

```cpp
std::mt19937& rng() {
    static std::mt19937 generator(
        static_cast<unsigned int>(
            std::chrono::high_resolution_clock::now()
                .time_since_epoch().count()) ^ std::random_device{}());
    return generator;
}
```

- `mt19937`：梅森旋转伪随机数生成器，标准库标配
- 种子 = **当前时间 ^ 设备随机数**。为什么不能只用 `random_device`？——本项目实际踩过坑：部分 MinGW 环境下 `random_device` 每次运行返回**固定值**，导致迷宫每次都一样；掺入时间后恢复正常

### 6.2 可复现（第 4 周 `--seed` 参数的基础）

```cpp
setSeed(42);   // Utils 提供：rng().seed(42)
```

同一种子 → 引擎产生相同的随机序列 → 相同的 shuffle 顺序 → **同一个迷宫**。这对性能测试和回归测试至关重要。

## 7. 为什么结果一定是完美迷宫（正确性）

设房间总数为 n（n = 奇数行 × 奇数列，如 5×5 有 4 个房间）。

**连通性（所有房间都会被挖到）**：
反证——若某房间永远没被访问，它周围全是墙，而它必与某个已访问房间相邻（内部房间彼此连通成一片）。DFS 会从相邻房间尝试朝它挖（方向枚举覆盖全部四邻），矛盾。

**无环（恰好 n−1 条通道）**：
每打通一条通道，必然是"已访问区域 → 一个新房间"（因为要求目标仍是 `'#'`）。n 个房间的连通图要连通，至少 n−1 条边；又因为每条边都引入一个新房间、从不连接两个旧房间，恰好形成 n−1 条边——**n 个点、n−1 条边、连通 → 树 → 无环**。

## 8. 复杂度分析

| 项 | 复杂度 | 说明 |
|------|:--:|------|
| 时间 | O(w·h) | 每个房间恰好被 carve 一次；每次 carve 做 4 次方向检查 |
| 空间（网格） | O(w·h) | 二维 char 矩阵 |
| 空间（递归栈） | 最深 O(w·h/4) | "蛇形"迷宫会一条道挖到底，递归深度 = 房间总数 |

> **已知风险**：递归深度随尺寸平方增长。21×21（约 100 层）毫无压力，但 201×201（约 1 万层）有爆栈风险——这正是项目计划第 4 周"递归 DFS 改写为显式 `std::stack` 迭代版"的原因。

实测参考（普通 PC，量级感受即可）：21×21 生成 <1ms；101×101 生成数 ms。
